# RunSift 运行故障调查 Agent 方案

RunSift 面向本地开发、CI 和无法复现的外场故障。开发者给出一个症状，
调查 Agent 按需查询运行证据，输出已确认的事实、定位范围、待验证的解释
以及下一步验证方法。首个场景是数据处理程序的批次漏数。

## v0.5 历史调查

1. `run` 或 `import` 生成案件证据包，保留来源和原始偏移。
2. `inspect` 提供概览、文本搜索、证据回读和批次对账，输出 JSON。
3. `investigate` 通过用户提供的本地适配器进行有轮数上限的只读调查，
   保留查询记录，校验发现及假设引用的事件 ID。

历史导入能精确映射时记录包内副本偏移，旧包继续支持解析事件回读。
字段映射由项目配置提供，底层证据查询适用于不同日志库。
批次对账依赖批次唯一性、完成标记和同口径的最终计数。阶段间预期一进一出，
合法过滤完成后再开始对账。记录差额只能说明日志中的计数不一致，
实际丢失需要输出文件、逐条确认或其他独立证据支持。

### 调查与验收

```bash
runsift import --case-id batch-demo examples/batch-shortfall.log
runsift inspect .runsift/cases/batch-demo check-batch A17 --profile examples/batch-profile.json
runsift investigate .runsift/cases/batch-demo --question 'A17 的差额出现在什么阶段？' \
  --profile examples/batch-profile.json -- ./my-adapter
```

本地适配器每轮从 stdin 接收调查 JSON，通过 stdout 返回一个动作。
完整样例应定位到 queued 与 confirmed 之间的 10 条差额。
删去最终计数应报告缺失阶段，冲突计数应保留两份证据并报告不足。
现有集成测试使用模拟适配器。后续用真实模型对比直接读文件、
单次分析和多轮调查，记录定位准确性、引用可复核性、缺证据时的误判
以及人工补充步骤。大文件流式导入与资源基准仍待实现。

## v0.6 活体取证

先支持进程仍在运行但输出停滞的场景。保留有时间和空间上限的近期窗口，
记录最后一次确认推进的位置。经用户授权后，按需进行有时限的线程栈采样，
结合进度及重复采样判断持续停滞。之后接入 Release 崩溃报告或 dump，
按构建标识匹配同一次发布归档的符号。

## v0.7 修复复核和案例反馈

在同一案件中保存修复前后的证据。用相同输入或可比批次核对原失败条件、
实际输出和业务约束。Agent 可基于已确认的案例提出新的解析映射、
业务检查或调查步骤。候选规则先回放验证，再经确认启用。
更换模型时重跑同一批案例，分别评估模型变化和工具本身的贡献。
